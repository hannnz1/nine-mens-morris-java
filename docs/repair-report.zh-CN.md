## 实际验证

- Java：Temurin 17.0.20.1、Maven 3.9.11；35 项测试通过，0 失败、0 错误、0 跳过。引擎 7，桌面 6，后端 22（包括 PostgreSQL 9）。后端与桌面 JAR 均构建成功。
- PostgreSQL：16.2，隔离实例 `127.0.0.1:55439`。`morris_repair_test` 专用于并发测试，`morris_repair_demo` 用于实际服务/客户端演示；使用当前 init.sql 显式初始化。没有连接或更改原业务数据。
- 前端：Node.js 24.18.0，11 项状态回归全部通过。`node --check` 通过。CI 添加 Node 22 前端检查，Java CI 基线保留 17。
- 双客户端：两个隔离 JavaScript 上下文运行实际 app.js 和本地 STOMP bundle，通过真实 HTTP/WebSocket 连接 Java 17 应用。覆盖双方推送、加入响应丢失、动作响应丢失、安全重试、断线落子、恢复入口、非法 SEND。使用 DOM 适配器，属于真实协议/状态验证，不能当作图形浏览器视觉验收。
- 完整 REST 演示脚本成功：交替落子、成磨、移除、同键重试、旧版本拒绝和最终棋盘读取。
- 检查 JavaScript 和 PowerShell 语法、HTML 中引用的 DOM ID、静态资源与 JAR 内容一致、init.sql 打包且无 Flyway/旧迁移、Compose 配置与 git diff。

测试中发现并修正了测试自身的两个问题：独立 Spring 测试上下文不应共用同名 H2 初始化库；加入重试恢复当前快照，不应断言数据库时间精度处理前后 JSON 字节完全相同。最终测试以身份、状态、版本和持久化结果作为证据，没有改变业务逻辑来迎合错误断言。

## 运行与复核

常规启动沿用 README：新库先执行 `backend/src/main/resources/db/init.sql`，设置 DB_URL/DB_USERNAME/DB_PASSWORD，再运行 Java 17 后端；Hibernate 仅 validate。Docker 空数据卷首次显式挂载初始化脚本，已有卷不自动重建。

```shell
mvn --batch-mode --no-transfer-progress verify
node --check backend/src/main/resources/static/app.js
node --test backend/src/test/frontend/session.test.cjs
```

真实 PostgreSQL 测试必须先初始化独立库，再设置 PG_TEST_URL；否则 PostgreSQL 测试会跳过。真实双客户端脚本需设置 MORRIS_DEMO_URL 指向测试服务后执行 `node scripts/verify-realtime.cjs`。这些脚本会写入新测试棋局，不能指向业务数据库。

完整 API 契约、现有库可选索引调整和面试说明见 [恢复设计](recovery-design.zh-CN.md)。

## 未验证项和取舍

- Docker daemon 当前不可用，因此只验证 Compose 配置，没有执行 Docker 镜像构建/容器运行。远端 GitHub CI 未触发，不声称远端通过。
- 没有图形浏览器视觉检查，也没有启动桌面 GUI 操作；桌面功能保留且回归测试通过。
- 快照恢复依赖后续网络和服务恢复；后台标签页定时器可能节流。推送不持久化，不保证每条事件送达，也不保证严格 2 秒同步。
- 凭证是 bearer secret，没有账号系统；关闭标签页、清除存储或主动清除后可能无法恢复。创建白方仍为一次签发，若创建响应丢失可能留下等待局；此次未扩展创建幂等框架。
- 幂等记录在演示规模下保留，不新增清理调度或历史版本迁移系统。没有进行性能压测，不声称性能提升、绝对可靠或端到端“恰好一次”。

## 面试时可以这样说

> 我先明确项目是单体棋局演示，优先保证操作正确和故障后能恢复。同一棋局的写操作在短事务内加悲观行锁；expectedVersion 用来发现用户基于旧棋盘操作；幂等键解决请求已成功但响应丢失后的重试，这三者并不重复。推送发生在提交之后，但推送失败不影响已经成功的业务，客户端通过快照追上状态。加入时先保存随机证明，避免用姓名冒领席位。数据库结构稳定，所以使用显式初始化 SQL 加 Hibernate 基本校验，省去版本迁移管理。我接受少量轮询和同步延迟，没有为演示项目增加消息队列、分布式事务或发件箱。
